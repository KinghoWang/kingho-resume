# 作品集项目案例去重设计

**日期：** 2026-08-20  
**状态：** 已通过结构评审，待用户复核书面规格

## 目标

将 `cases.html` 从“简历项目卡复述 + 独立 Demo 目录”改为三个可独立阅读的正常项目案例。案例允许用一句必要背景和一句结果建立上下文，但主要篇幅必须补充简历未展开的关键判断、方案逻辑和合理归因，避免让面试官为重复信息付出阅读成本。

## 核心原则

1. **案例可独立阅读。** 不要求面试官在简历和作品集之间来回对照。
2. **只保留最小必要重复。** 背景和结果可以各简述一次；不得再次完整复制简历里的三步项目卡。
3. **解释为什么这样做。** 每个案例必须写出关键判断、方案成立的原因和人机分工。
4. **区分结果与归因。** 明确数据支持到什么程度，不把同期表现或相关变化包装成单一因果。
5. **Demo 就近出现一次。** Demo 直接放在对应案例末尾，不再建立第二套“全部 Demo”目录。

## 页面信息架构

页面顶部保持返回入口和一次脱敏说明，主标题改为“作品集 · 项目案例”。脱敏说明只交代名称、绝对值和界面素材的处理边界，不再罗列 Demo 类型或数量。正文只保留以下三个案例，顺序与简历一致：

1. 企微获客链路改造
2. AI 创意生产与投放验证
3. AI 广告日报与问题排查

每个案例统一使用以下结构：

1. 项目标题与角色
2. 一段必要背景
3. 关键判断
4. 方案逻辑或执行流程
5. 结果验证
6. 归因边界
7. 对应 Demo 入口

视觉上采用全宽项目段落和细分隔线，不再使用与简历相同的三栏摘要卡，也不增加独立证据墙、能力总结或重复 Demo 目录。

## 案例内容合同

### 01 企微获客链路改造

**必要背景：** 原链路要求用户在 H5 长按二维码，再从系统菜单选择识别；中老年主力用户不熟悉这一步，容易在加微前退出。

**关键判断：** 问题不只是链路多一步，而是关键动作不符合目标用户的常用操作习惯。优化目标是移除长按和菜单判断，不是单纯减少页面数量。

**方案逻辑：** 小程序无法直接调起企微获客助手，但可以打开企微客服会话。以客服会话为中转，自动发送文案和卡片，两者都指向同一获客链接，用户点击任一入口即可继续添加微信。

**结果验证：** 曝光-加微率提升 50% 以上，曝光-地址率提升 40% 以上；广告主后续转化未下降。

**归因边界：** 指标为相对原链路的提升，绝对值已脱敏。后续转化未下降作为质量护栏。CPM 同步提升只作为平台效率结果展示，不单独归因为前端链路改造。

**Demo：** `demo-wecom-flow.html`。保留 `cases.html#case-lianlu` 旧锚点及 Demo 返回链接合同。

### 02 AI 创意生产与投放验证

**必要背景：** 新 SKU 素材制作需要复用历史有效经验，同时不能让缺少视觉判断能力的 Agent 自行决定创意方向。

**关键判断与分工：** 人工查看广告素材逐秒表现和分段聚合数据，找出可复用与需优化部分，并形成新 SKU 制作建议；Agent 负责按已确定方向执行剪辑，人工负责最终抽检。

**执行流程：** 素材洞察 → 制作建议 → 悟空任务卡与剪辑脚本执行 → 自动质检与白名单自修 → 人工抽检 → 投放验证。

**结果验证：** 新素材以同期同 SKU 全量素材为基准，CPM 与 CTCVR 综合表现处于中上游；减少人工逐条跟进与重复制作投入，但不量化未经确认的节省比例。

**归因边界：** 结果支持“该生产链路可以稳定产出不差的可投素材”，不包装为头部爆款，也不声称全部投放表现由 AI 单独造成。

**Demo：**

- `demo-creative.html`：逐秒表现、分段聚合与双素材对比。
- `demo-wukong.html`：任务卡、自动质检、失败停车、白名单自修与人工审校。
- `demo-advideo.html`：仅作为外部素材参考能力展示，不宣称已经接入本项目的生产链路，不公开采集细节。

### 03 AI 广告日报与问题排查

**必要背景：** 广告日报需要快速发现异常，同时避免运营直接采用模型给出的未经核验结论。

**关键判断与分工：** AI 只负责按固定指标口径汇总核心表现、异常变化和待排查线索；运营在公司内部大数据看板 Grafana-Lite 下钻，用明细数据核验问题与影响范围，并作最终判断。

**执行流程：** 固定指标口径 → 数分机器人生成日报和线索 → Grafana-Lite 下钻核验 → 将确认的问题、数据依据与影响范围整理成 MRD → 反馈产研。

**结果验证：** 日报整理及数据排查从小时级缩短至分钟级；每周向产研提交 1 至 2 份 MRD。

**归因边界：** 不声明 MRD 的采纳或上线数量，不把最终业务判断或问题解决归给 AI，也不把 Grafana-Lite 的建设归属作为卖点。

**Demo：**

- `demo-shufen.html`：日报线索、异常检出与归因下钻过程。
- `demo-eval.html`：22 例黄金集、3 模型 × 2 配置与回归门禁。

## 验收标准

1. 页面只包含三个项目案例，顺序与简历一致。
2. 三个案例均包含必要背景、关键判断、方案逻辑、结果验证、归因边界和对应 Demo。
3. 六个 Demo URL 在 `cases.html` 中各出现一次，不存在第二套 Demo 目录。
4. 页面不出现算法流量存废、财务对账数据可信性或旧三栏简历项目卡。
5. `#case-lianlu` 及企微 Demo 返回链接继续有效。
6. 中英文首页入口、README 数量和页面元信息口径一致。
7. Playwright 回归通过；360、390、1024、1440 视口无横向溢出、截断或重叠。
8. 桌面和手机截图中三个案例均可见，Demo 链接可点击，控制台无错误。
