# 悟空 Agent 生产管线交互 Demo 设计规格

- 日期：2026-08-13
- 状态：用户已确认采用高保真静态交互方案
- 目标页面：`demo-wukong.html`
- 接入位置：中英文简历悟空项目卡、`cases.html`

## 1. 目标

为「悟空」项目补齐可操作的公开证据。访问者应能亲手走完：

`创建任务 -> 文件化执行 -> 验证失败停车 -> 白名单自修 -> 人工审校 -> 局部重做 -> 按秒留言 -> 审计回填`

Demo 复现悟空真实的任务卡、验证门、人工契约与审计闭环，但只运行浏览器内的确定性状态机，不连接悟空后台、模型 API、本机文件或生产管线。

## 2. 信息架构

页面采用与悟空桌面应用一致的安静工作台布局：

1. 顶栏：悟空名称、演示状态、返回作品集、重置。
2. 阶段栏：创建任务、Agent 执行、人工耳审、审计反馈。
3. 主工作区：当前阶段的表单、任务卡、验证结果、审校契约或留言回填。
4. 右侧证据栏：25 张任务卡进度、3 段状态、事件日志与关键机制。
5. 隐私说明：静态脱敏演示、不连接生产环境、不含真实素材。

## 3. 状态机

| 状态 | 用户可见结果 | 合法操作 |
| --- | --- | --- |
| `SETUP` | 合成素材表单 | 生成任务卡、自动演示 |
| `RUNNING` | 任务卡开始执行 | 运行至下一质检门 |
| `GATE_FAILED` | 音频缓存门失败，流程停车 | 选择白名单动作并修复 |
| `GATE_RECOVERED` | 同一卡最后标记由失败变通过 | 继续至人工耳审 |
| `REVIEW` | 三条人工耳审契约 | 每条选择通过或重做并提交 |
| `REWORK` | 仅重做项缓存失效 | 局部重做并重新过门 |
| `COMMENTS` | 合成成片与按秒留言面板 | 添加并提交留言 |
| `AUDIT_PENDING` | 留言等待审计者翻译 | 模拟审计回填 |
| `COMPLETE` | 25/25，交付闭环完成 | 重置演示 |

状态转换只能由明确事件触发。`GATE_FAILED` 不允许直接进入耳审；Agent 文本中出现“已完成”不改变状态。失败卡允许后续通过，进度按同一卡最后一个验证标记计算。

## 4. 核心交互

### 4.1 创建任务

- 表单固定使用合成值：`课程素材 A`、`参考节奏 B`、`兴趣课程体验包`、`示例品牌`、`course_demo_01`。
- 五个字段均必填；缺失时在表单内提示。
- 生成后展示 3 个阶段、25 张任务卡，且说明同名任务不会覆盖既有卡。

### 4.2 验证门与恢复

- 点击“运行至下一质检门”后到达 11/25，并显示音频缓存门失败。
- 同时展示 Agent 自述“已完成”，但证据栏仍为失败。
- 自修只允许三项：重跑脚本、清缓存、调整几何数值。本次预选“清缓存并原样重跑”。
- “修改门脚本”作为禁用选项出现，说明验证规则不可由执行 Agent 改写。
- 修复后同一卡显示 `FAIL -> PASS`，才能进入耳审。

### 4.3 人工耳审与局部重做

- 展示三条合成语句；每条使用“通过 / 重做”分段控件。
- 所有条目完成判断前提交按钮不可用。
- 演示路径要求第二条判为重做，其余通过。
- 提交后只让第二条缓存失效，并明确其余已通过内容保持冻结。

### 4.4 按秒留言与审计回填

- 合成播放器不加载真实媒体，以 CSS 时间轴表示 30 秒成片。
- 默认时间点为 `18.4s`，留言为“这一句口播偏快，停顿再留半拍”。
- 自由文本提交后状态为“等待审计”，不直接发给执行 Agent。
- 审计回填将其翻译为确定动作：“拉长该句 0.4 秒并重跑音频门”，随后完成 25/25。

### 4.5 断点续跑

- 使用 `sessionStorage` 仅保存当前演示状态与合成选择；刷新同一标签页可恢复。
- 不保存自由输入、用户身份、网络信息或生产数据。
- “重置演示”清除会话状态并回到 `SETUP`。

## 5. 自动演示

“自动演示完整闭环”按上述成功路径依次推进。任何真实点击或键盘操作都会停止自动编排、保留当前状态并交还用户；重置会清除全部计时器。`prefers-reduced-motion` 下缩短过渡但不跳过状态。

## 6. 作品集重排

简历项目区统一为三组：

1. 数分机器人 × Eval：生产产品与质量门禁合为一组，保留数分和 Eval 两个入口。
2. 悟空 × Agent 生产管线：增加 `demo-wukong.html` 入口。
3. adquery-lite：保留数据底座叙事，链接作品集中的对账案例。

`cases.html` 第一层改为三组核心项目；竞品广告情报与创意分段诊断放入“扩展在线 Demo”。站点口径为“5 个 AI / 数据在线 Demo + 策略产品案例”，企微交互 Demo 继续归属于策略案例，不混入 AI / 数据 Demo 计数。

## 7. 脱敏与安全边界

- 不包含真实视频、音频、人物、品牌、SKU、客户、文案、二维码或内部项目代号。
- 不包含绝对路径、用户名、工作目录、任务日志、命令输出、哈希、模型 Key、余额、API 地址、MCP 配置或会话 ID。
- 不读取 AgentApp 的凭据、会话、日志、任务卡或契约文件。
- 不使用 `fetch`、WebSocket、iframe、外部链接或第三方资源。
- 页面明确标注“静态脱敏演示”，不得声称正在调用真实模型或生产管线。

## 8. 响应式与可访问性

- `>= 980px` 为主工作区 + 证据栏；更窄时上下排列。
- 360、390、1024、1440 四档不得横向溢出。
- 所有按钮最小高度 44px；状态不只依赖颜色表达。
- 分段控件可用键盘操作；错误与状态更新通过 `aria-live` 宣告。
- 动态内容有固定最小高度，避免状态切换造成页面剧烈跳动。

## 9. 验收标准

- 从 `SETUP` 可完整操作至 `COMPLETE`。
- 质检失败后不能跳过，Agent 自述不能改变进度。
- 白名单修复后同一卡显示失败到通过的证据。
- 人工审校未完成时不能提交；局部返工不影响冻结项。
- 留言先进入审计，回填后才成为执行动作。
- 刷新可恢复质检失败等中间状态，重置可彻底清空。
- 页面没有网络请求、真实媒体、真实路径或敏感配置。
- 中英文简历均为三组核心项目，悟空均有 Demo 入口；数分机器人卡同时包含 Eval 入口。
- 作品集保留五个 AI / 数据 Demo 的全部入口，竞品与创意页面不删除。
