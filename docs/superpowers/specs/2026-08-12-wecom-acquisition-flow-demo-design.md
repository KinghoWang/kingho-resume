# 企微获客链路交互 Demo 设计规格

- 日期：2026-08-12
- 状态：已完成交互设计，待用户复核书面规格
- 目标页面：`demo-wecom-flow.html`
- 接入位置：`cases.html#case-lianlu`

## 1. 背景与目标

`cases.html` 已有「企微获客链路改造」案例，但当前链路图只能说明结构，不能让面试官亲手体验旧链路的长按、系统菜单等摩擦，也不能直观看到新链路自动下发文案和卡片后的操作缩短。

本次新增一个完全脱敏的交互 Demo，用同一广告起点、同一企业联系人终点，对照模拟两条链路：

1. 原链路：广告 -> H5 -> 长按二维码 -> 系统菜单 -> 企业联系人 -> 已添加。
2. 新链路：广告 -> 企微客服会话 -> 自动下发含获客链接的文案和卡片 -> 点击任一入口 -> 企业联系人 -> 已添加。

成功标准：用户无需阅读说明，也能通过操作感知「原链路依赖长按与系统菜单，新链路把高摩擦动作替换为点击入口」。

## 2. 范围

### 2.1 本次包含

- 独立静态页面 `demo-wecom-flow.html`。
- 桌面端双手机并排，手机端上下排列。
- 手动操作与单次自动演示两种模式。
- 两条链路各自独立的明确状态机。
- 原链路真实 `0.8 秒` 长按判定。
- 新链路自动下发文案和卡片，两个入口进入同一联系人页。
- 自动演示中途由用户接管。
- 同时重置两条链路。
- 根据状态转移元数据计算的标准必需操作、高摩擦动作和完成状态。
- `cases.html` Case 01 增加「打开交互 Demo」入口。
- 桌面、手机、鼠标、触屏和键盘的核心流程验收。

### 2.2 本次不包含

- 不接入真实企微、获客助手、二维码或外部链接。
- 不读取、提交或保存用户信息。
- 不上传或嵌入两段真实业务视频，不使用视频截图。
- 不模拟添加联系人之后的地址填写或后续转化。
- 不新增业务 KPI，不根据 Demo 推算效果数据。
- 不改写 Case 01 已有背景、动作、成果和 KPI 内容。
- 不引入前端框架、构建工具、后端或埋点。

## 3. 已选方案

采用纯 HTML、CSS、JavaScript 的明确有限状态机。页面可直接由 GitHub Pages 托管，无外部依赖。

### 3.1 方案比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 明确状态机 | 状态可追踪；手动、自动、暂停、重置共用同一逻辑；容易验收 | 比直接切 DOM 多一层状态定义 | 采用 |
| 直接操作 DOM | 初始代码较短 | 自动演示与用户接管容易错位，计时器难清理 | 不采用 |
| 引入前端框架 | 组件边界清楚 | 对单页静态 Demo 过重，增加依赖和部署面 | 不采用 |

### 3.2 核心原则

- 状态决定画面，事件决定状态转移。
- 手动模式和自动模式调用同一套状态转移，不维护两份流程。
- 所有自动计时器进入统一注册表，暂停、重置和重播时一次清空。
- DOM 只负责渲染和收集交互，不直接决定业务状态。
- 文案链接与卡片入口分属两个控件，但派发同一个获客入口事件。

## 4. 页面信息架构

页面从上到下分为五个区域：

1. 顶栏：返回作品集、页面标题、脱敏标识。
2. 控制栏：手动操作 / 自动演示分段控制、播放状态、重置按钮。
3. 对照舞台：原链路手机、新链路手机，以及各自的步骤状态栏。
4. 对比结果：标准必需用户操作、高摩擦动作、获客入口和完成状态。
5. 辅助状态：短按失败、菜单无效项、自动暂停等即时反馈，使用稳定高度的状态区或轻量 toast，不推动主布局。

`cases.html` 在 Case 01 的三段故事卡之后、现有链路对比面板之前加入一个入口，链接到 `demo-wecom-flow.html`。Demo 页顶栏返回 `cases.html#case-lianlu`。

## 5. 全局状态模型

```text
DemoState = {
  mode: "manual" | "auto",
  countdown: null | 3 | 2 | 1,
  oldLane: OldLaneState,
  newLane: NewLaneState,
  timerRegistry: Map<TimerId, "demo" | "lane">,
  feedback: null | FeedbackMessage
}
```

`timerRegistry` 是运行时控制对象，不进入可见业务状态。`demo` 计时器只编排倒计时和自动操作；`lane` 计时器表示客服会话自身的文案 / 卡片下发。重置和重播清空两类计时器；自动转手动或页面进入后台只清空 `demo` 计时器，再按当前新链路状态补齐仍应发生的消息下发。

## 6. 原链路状态机

### 6.1 状态

| 状态 | 画面 | 可执行事件 |
| --- | --- | --- |
| `OLD_AD` | 与新链路一致的虚构健康资料广告 | `CLAIM_CLICK` |
| `OLD_H5` | H5 资料页、纯 CSS 伪二维码、长按提示 | `HOLD_START` |
| `OLD_HOLDING` | 保持 H5，显示 `0-0.8 秒` 长按进度 | `HOLD_COMPLETE`、`HOLD_ABORT` |
| `OLD_MENU` | 模拟系统菜单 | `MENU_OPEN_CONTACT`、`MENU_CANCEL`、`MENU_SHARE`、`MENU_SAVE` |
| `OLD_CONTACT` | 脱敏企业联系人详情 | `ADD_CONTACT` |
| `OLD_ADDED` | 同一联系人页的已添加状态 | 无推进事件，可重置或重播 |

### 6.2 状态转移

| 当前状态 | 事件 | 下一状态 | 用户动作 | 高摩擦 |
| --- | --- | --- | ---: | ---: |
| `OLD_AD` | `CLAIM_CLICK` | `OLD_H5` | 1 | 0 |
| `OLD_H5` | `HOLD_START` | `OLD_HOLDING` | 0 | 0 |
| `OLD_HOLDING` | `HOLD_COMPLETE` | `OLD_MENU` | 1 | 1 |
| `OLD_HOLDING` | `HOLD_ABORT` | `OLD_H5` | 0 | 0 |
| `OLD_MENU` | `MENU_OPEN_CONTACT` | `OLD_CONTACT` | 1 | 1 |
| `OLD_MENU` | `MENU_CANCEL` | `OLD_H5` | 0 | 0 |
| `OLD_MENU` | `MENU_SHARE` / `MENU_SAVE` | `OLD_MENU` | 0 | 0 |
| `OLD_CONTACT` | `ADD_CONTACT` | `OLD_ADDED` | 1 | 0 |

标准成功路径共 4 个必需用户操作，其中 2 个为高摩擦动作：长按、系统菜单选择。

### 6.3 长按规则

- 鼠标或触屏 `pointerdown` 开始计时，达到 `800ms` 派发 `HOLD_COMPLETE`。
- `800ms` 前发生 `pointerup`、`pointercancel`、移出有效区域或窗口失焦，派发 `HOLD_ABORT`，提示「请长按二维码」。
- 完成后松手不应重复派发事件。
- 禁止浏览器原生右键 / 长按菜单，页面只显示脱敏模拟菜单。
- 键盘用户聚焦伪二维码后，按住空格 `800ms` 等价于长按；提前松开等价于短按失败。
- 「取消」返回 H5 并要求重新长按；「转发给朋友」「保存图片」只显示演示提示，仍停在系统菜单。

## 7. 新链路状态机

### 7.1 状态

| 状态 | 画面 | 可执行事件 |
| --- | --- | --- |
| `NEW_AD` | 与原链路一致的虚构健康资料广告 | `CLAIM_CLICK` |
| `NEW_CHAT` | 已打开客服会话，等待自动消息 | 系统事件 `SEND_TEXT` |
| `NEW_TEXT_SENT` | 显示一段含获客链接的文案 | `ACQUISITION_CLICK`、系统事件 `SEND_CARD` |
| `NEW_BOTH_SENT` | 文案与含同一链接的卡片同时可见 | `ACQUISITION_CLICK` |
| `NEW_CONTACT` | 与原链路同结构的脱敏企业联系人详情 | `ADD_CONTACT` |
| `NEW_ADDED` | 同一联系人页的已添加状态 | 无推进事件，可重置或重播 |

### 7.2 状态转移

| 当前状态 | 事件 | 下一状态 | 用户动作 | 高摩擦 |
| --- | --- | --- | ---: | ---: |
| `NEW_AD` | `CLAIM_CLICK` | `NEW_CHAT` | 1 | 0 |
| `NEW_CHAT` | `SEND_TEXT` | `NEW_TEXT_SENT` | 0 | 0 |
| `NEW_TEXT_SENT` | `SEND_CARD` | `NEW_BOTH_SENT` | 0 | 0 |
| `NEW_TEXT_SENT` / `NEW_BOTH_SENT` | `ACQUISITION_CLICK` | `NEW_CONTACT` | 1 | 0 |
| `NEW_CONTACT` | `ADD_CONTACT` | `NEW_ADDED` | 1 | 0 |

标准成功路径共 3 个必需用户操作，无高摩擦动作。文案内链接和整张卡片都派发 `ACQUISITION_CLICK`，进入同一个联系人状态，不进行真实跳转。

文案使用保留域名 `https://work.example/link` 作为不可访问的脱敏示意。文案、卡片、客服名称和头像均为虚构重绘。

## 8. 手动模式

- 初始模式为手动，两台手机都处于各自广告起点。
- 两条链路互不联动，操作一边不会推进另一边。
- 新链路点击广告后，页面以 `lane` 计时器自动依次派发 `SEND_TEXT` 和 `SEND_CARD`；这两个系统动作不计入用户操作。
- 文案出现后即可点击获客链接；若在卡片出现前点击，取消尚未执行的卡片计时器并直接进入联系人页。
- 「重置两条链路」清空计时器、长按进度、反馈和操作统计，切回手动模式，两边同时回到广告起点。
- 已完成状态不自动循环。

## 9. 自动演示

### 9.1 启动与时间线

点击「自动演示」后：

1. 清空所有旧计时器和反馈。
2. 两条链路重置到广告起点。
3. 显示 `3、2、1` 倒计时。
4. 倒计时结束后，两边同时按标准成功路径推进。

倒计时结束记为 `T+0`，目标时间线如下：

| 时间 | 原链路 | 新链路 |
| --- | --- | --- |
| `T+0.0s` | 点击广告，进入 H5 | 点击广告，打开客服会话 |
| `T+0.8s` | 停留在 H5 | 自动下发含链接文案 |
| `T+1.4s` | 开始模拟长按 | 自动下发含链接卡片 |
| `T+2.2s` | 长按完成，弹出系统菜单 | 停留并展示双入口 |
| `T+3.2s` | 停留在系统菜单 | 点击卡片，进入联系人页 |
| `T+4.6s` | 停留在系统菜单 | 点击添加，显示已添加 |
| `T+5.0s` | 选择联系人菜单，进入联系人页 | 已完成并保持 |
| `T+7.7s` | 点击添加，显示已添加 | 已完成并保持 |

允许视觉动画存在少量渲染延迟，但状态事件顺序不得变化。新链路先完成后必须停留在 `NEW_ADDED`，等待原链路完成，以呈现操作差异。

### 9.2 用户接管

- 自动演示时，用户在任一手机内发生 `pointerdown` 或键盘操作，立即清空全部 `demo` 计时器并将模式切为手动。
- 若该交互命中了当前状态的有效控件，在暂停后继续处理同一个事件；点击空白区域只暂停，不推进状态。
- 接管后保留两边当前状态，不自动回到起点。
- 若接管时新链路处于 `NEW_CHAT` 或 `NEW_TEXT_SENT`，重新注册对应的 `lane` 计时器，让尚未完成的文案 / 卡片继续下发；不会因暂停演示而卡死在半成品状态。
- 页面切到后台时，自动演示同样停止并保留当前状态；回到前台后按上述规则补齐会话消息，避免后台计时器漂移。
- 自动演示只播放一次；结束后可重播或切回手动。

## 10. 对比指标口径

底部对比区不使用散落在 DOM 中的硬编码数字，而是读取状态转移表的元数据计算：

- `用户动作`：标记为 `userAction = 1` 的成功状态转移数量。
- `高摩擦动作`：标记为 `highFriction = 1` 的成功状态转移数量。
- `获客入口`：原链路为单一伪二维码，新链路为文案链接与整张卡片两个入口。
- `完成状态`：根据当前状态显示「未开始 / 进行中 / 已添加」。

在自动演示中，指标表示「该标准路径要求用户完成的动作」，即使事件由演示器代为派发，最终仍显示原链路 `4`、新链路 `3`。短按失败、取消菜单等无效尝试只用于即时反馈，不改变标准路径操作口径。

## 11. 视觉与响应式规则

- 采用已批准的浅色中性视觉系统；旧链路摩擦节点使用克制红色，新链路通路使用绿色。
- 两部手机的外壳、状态栏、应用栏、联系人页、字体与间距保持一致，只让流程内容产生差异。
- 不使用真实品牌 Logo、真实头像、真实商品图、真实二维码或视频截图。
- 伪二维码仅由 CSS 图案构成，不应能被扫码识别。
- 固定手机比例、步骤区域宽度和反馈区高度，状态切换不得导致整体布局跳动。
- `>= 980px`：双链路并排；每条链路内手机与步骤栏并排。
- `< 980px`：两条链路上下排列。
- `< 580px`：单手机居中，步骤栏改为两列或单列，页面不得横向滚动。
- 所有可操作区域最小触控尺寸为 `44 x 44px`；最长中文文案必须换行且不溢出。
- 支持 `prefers-reduced-motion`：减少位移动画，但不跳过状态和结果。

## 12. 组件与职责

实现保持单页、无框架，但内部职责分离：

| 单元 | 职责 |
| --- | --- |
| `TRANSITIONS` | 定义新旧链路合法事件、下一状态和指标元数据 |
| `dispatch(lane, event)` | 校验并执行状态转移；非法事件无副作用 |
| `renderLane(lane)` | 根据单条链路状态渲染手机和步骤栏 |
| `renderMetrics()` | 从状态转移记录计算并渲染对比区 |
| `scheduleAutoDemo()` | 注册 `demo` 倒计时和自动事件，不直接改 DOM |
| `scheduleLaneMessages()` | 根据新链路当前状态注册尚未完成的 `lane` 消息下发 |
| `cancelAutomation()` | 清空 `demo` 计时器、保留业务状态，并补齐必要的 `lane` 计时器 |
| `resetAll()` | 恢复确定的初始状态 |
| `bindInteractions()` | 将点击、长按、键盘和模式控件映射为事件 |

页面不需要服务端、网络请求、LocalStorage 或跨页面状态。

## 13. 错误与边界处理

- 非法事件不改变状态，也不累计指标。
- 重复快速点击通过状态校验自然去重，不允许跨过中间状态。
- 重置和重播前必须清空两类计时器，避免多轮演示叠加。
- `pointercancel`、窗口失焦、切换标签页都会终止未完成长按。
- 计时器回调执行前再次核对计时器类型、当前模式和状态；状态已变化则回调失效。
- 浏览器不支持触控时仍可使用鼠标和键盘完成全部核心流程。
- 所有提示均为本地 UI，不调用系统分享、保存或通讯录权限。

## 14. 脱敏与公开边界

- 页面显式标注「虚构重绘 · 无真实素材 · 无真实链接」。
- 企业名称、客服名称、联系人、头像、文案、商品封面均使用虚构内容。
- 链接只使用 `.example` 保留域名。
- 不包含内部 URL、客户名称、数据表名、UID、Cookie、Token、密钥或本机路径。
- 原视频继续只留本地素材目录，不进入公开仓库。
- `cases.html` 保留 `+50%+`、`+40%+`、后转无损和效率 CPM 提升等已确认脱敏口径；Demo 不创造绝对值。

## 15. 验收清单

### 15.1 功能

- 两条手动路径可从共同广告起点走到已添加。
- 原链路短按失败，长按达到 `0.8 秒` 才弹出模拟系统菜单。
- 原链路菜单取消后返回 H5；转发和保存不离开流程。
- 新链路文案和卡片自动出现，点击任一入口进入同一联系人页。
- 手动模式两边互不联动。
- 自动演示倒计时后同时开始，新链路先完成，原链路后完成。
- 自动演示中点击任一手机可暂停并从当前状态继续。
- 在 `NEW_CHAT` 或 `NEW_TEXT_SENT` 接管后，剩余消息仍会自动补齐，不会卡死。
- 重置和重播不会残留旧计时器、长按进度或统计。
- 对比指标与状态转移表一致：标准完成后原链路 `4 / 2`，新链路 `3 / 0`（用户动作 / 高摩擦动作）。

### 15.2 视觉与可用性

- 在桌面 `1440 x 900`、笔记本 `1024 x 768`、手机 `390 x 844` 和窄屏 `360 x 800` 检查。
- 无空白画面、横向溢出、文字截断、控件重叠或状态切换跳动。
- 中文字体正常，伪二维码、卡片、联系人页和状态高亮正确渲染。
- 手机端上下排列，点击区域足够，长按不会触发浏览器默认菜单。
- 键盘可完成广告点击、长按、菜单选择和添加。
- `prefers-reduced-motion` 下流程仍完整。

### 15.3 集成与发布

- `cases.html` 的 Case 01 按钮能打开 Demo，Demo 返回链接能回到 `#case-lianlu`。
- 全站本地链接扫描无缺失。
- 公开敏感信息扫描无命中。
- GitHub Pages 部署成功后使用缓存破除参数核对线上 HTML。
- 线上手动流程、自动流程和移动端截图与本地验收一致。
