# 企微获客链路交互 Demo 设计规格

- 日期：2026-08-12
- 状态：用户已于 2026-08-12 通过交互规格，并确认净室高保真升级边界
- 目标页面：`demo-wecom-flow.html`
- 接入位置：`cases.html#case-lianlu`

## 1. 背景与目标

`cases.html` 已有「企微获客链路改造」案例，但当前链路图只能说明结构，不能让面试官亲手体验中老年用户为什么会卡在旧链路的长按与系统菜单，也不能直观看到新链路如何把陌生手势换成用户熟悉的点击。

本次新增一个完全脱敏的交互 Demo，用同一广告起点、同一企业联系人终点，对照模拟两条链路：

1. 原链路：广告 -> H5 -> 长按二维码 -> 系统菜单 -> 企业联系人 -> 已添加。
2. 新链路（公开抽象）：广告 -> 可点击承接页 -> 点击文案或卡片 -> 企业联系人 -> 已添加。

成功标准：用户无需阅读说明，也能通过操作感知「原链路依赖中老年用户不熟悉的长按与系统菜单，新链路把陌生手势替换为熟悉的点击入口」。链路少一步只是结果，不作为核心价值叙事。

视觉成功标准：手机内部界面不再是抽象示意，而是按用户提供的两段本地视频逐镜头重绘。界面类型、信息密度、布局、色彩、控件、滚动内容、加载过渡和交互时序与视频保持一致；所有可能识别真实业务主体的信息使用等位虚构内容替换。

## 2. 范围

### 2.1 本次包含

- 独立静态页面 `demo-wecom-flow.html`。
- 桌面端双手机并排，手机端上下排列。
- 手动操作与单次自动演示两种模式。
- 两条链路各自独立的明确状态机。
- 原链路真实 `0.8 秒` 长按判定。
- 新链路展示可直接点击的文案和卡片，两个入口都可继续完成流程。
- 自动演示中途由用户接管。
- 同时重置两条链路。
- 对比目标用户需要掌握的操作门槛、入口选择和当前完成状态。
- `cases.html` Case 01 增加「打开交互 Demo」入口。
- 桌面、手机、鼠标、触屏和键盘的核心流程验收。
- 原链路按视频还原信息流广告、白色长页、二维码、iOS 风格菜单和浅色联系人页。
- 新链路使用抽象承接页展示文案和卡片入口，具体承接机制与平台能力配置不进入公开版本。
- 手机内部关键状态按用户层交互进行视觉验收，不公开原始业务视频或实施细节。

### 2.2 本次不包含

- 不接入真实企微能力、二维码或外部链接。
- 不读取、提交或保存用户信息。
- 不上传或嵌入两段真实业务视频，不使用视频截图或从视频裁出的真实素材。
- 不模拟添加联系人之后的地址填写或后续转化。
- 不新增业务 KPI，不根据 Demo 推算效果数据。
- 不改写 Case 01 的成果与 KPI；可按用户确认纠正背景、动作和价值叙事。
- 不引入前端框架、构建工具、后端或埋点。

## 3. 已选方案

采用纯 HTML、CSS、JavaScript 的明确有限状态机。页面可直接由 GitHub Pages 托管，无外部依赖。

### 3.1 方案比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 明确状态机 | 状态可追踪；手动、自动、暂停、重置共用同一逻辑；容易验收 | 比直接切 DOM 多一层状态定义 | 采用 |
| 直接操作 DOM | 初始代码较短 | 自动演示与用户接管容易错位，计时器难清理 | 不采用 |
| 引入前端框架 | 组件边界清楚 | 对单页静态 Demo 过重，增加依赖和部署面 | 不采用 |

### 3.2 核心原则

- 状态决定画面，事件决定状态转移。
- 手动模式和自动模式调用同一套状态转移，不维护两份流程。
- 所有自动计时器进入统一注册表，暂停、重置和重播时一次清空。
- DOM 只负责渲染和收集交互，不直接决定业务状态。
- 文案与卡片入口分属两个控件，但派发同一个继续操作事件。

## 4. 页面信息架构

页面从上到下分为五个区域：

1. 顶栏：返回作品集、页面标题、脱敏标识。
2. 控制栏：手动操作 / 自动演示分段控制、播放状态、重置按钮。
3. 对照舞台：原链路手机、新链路手机，以及各自的步骤状态栏。
4. 对比结果：目标用户需要掌握的操作、后续判断、获客入口和完成状态。
5. 辅助状态：短按失败、菜单无效项、自动暂停等即时反馈，使用稳定高度的状态区或轻量 toast，不推动主布局。

`cases.html` 在 Case 01 的三段故事卡之后、现有链路对比面板之前加入一个入口，链接到 `demo-wecom-flow.html`。Demo 页顶栏返回 `cases.html#case-lianlu`。

## 5. 全局状态模型

```text
DemoState = {
  mode: "manual" | "auto",
  countdown: null | 3 | 2 | 1,
  oldLane: OldLaneState,
  newLane: NewLaneState,
  timerRegistry: Map<TimerId, "demo" | "navigation" | "hold">,
  feedback: null | FeedbackMessage
}
```

`timerRegistry` 是运行时控制对象，不进入可见业务状态。`demo` 计时器只编排倒计时和自动操作，`navigation` 计时器表示公开演示中的本地加载过渡，`hold` 计时器只负责原链路长按判定。重置和重播清空三类计时器；自动转手动或页面进入后台只清空 `demo` 计时器，并按当前状态补齐本地页面过渡。操作新链路不得中断旧链路正在进行的长按。

## 6. 原链路状态机

### 6.1 状态

| 状态 | 画面 | 可执行事件 |
| --- | --- | --- |
| `OLD_AD` | 与新链路一致的虚构健康资料广告 | `CLAIM_CLICK` |
| `OLD_H5` | 白色 H5 长页：资料封面、长按说明、领取名单、伪二维码和底部领取条 | `HOLD_START` |
| `OLD_HOLDING` | 保持 H5，显示 `0-0.8 秒` 长按进度 | `HOLD_COMPLETE`、`HOLD_ABORT` |
| `OLD_MENU` | 与视频一致的 iOS 风格底部操作菜单 | `MENU_OPEN_CONTACT`、`MENU_CANCEL`、`MENU_SHARE`、`MENU_SAVE` |
| `OLD_CONTACT` | 浅色企业联系人资料页 | `ADD_CONTACT` |
| `OLD_ADDED` | 同一联系人页的已添加状态 | 无推进事件，可重置或重播 |

### 6.2 状态转移

| 当前状态 | 事件 | 下一状态 |
| --- | --- | --- |
| `OLD_AD` | `CLAIM_CLICK` | `OLD_H5` |
| `OLD_H5` | `HOLD_START` | `OLD_HOLDING` |
| `OLD_HOLDING` | `HOLD_COMPLETE` | `OLD_MENU` |
| `OLD_HOLDING` | `HOLD_ABORT` | `OLD_H5` |
| `OLD_MENU` | `MENU_OPEN_CONTACT` | `OLD_CONTACT` |
| `OLD_MENU` | `MENU_CANCEL` | `OLD_H5` |
| `OLD_MENU` | `MENU_SHARE` / `MENU_SAVE` | `OLD_MENU` |
| `OLD_CONTACT` | `ADD_CONTACT` | `OLD_ADDED` |

原链路的决定性门槛是：用户必须成功完成长按，并在弹出的系统菜单中选对入口。路径动作数量仅用于还原过程，不作为价值结论。

### 6.3 长按规则

- 鼠标或触屏 `pointerdown` 开始计时，达到 `800ms` 派发 `HOLD_COMPLETE`。
- `800ms` 前发生 `pointerup`、`pointercancel`、移出有效区域或窗口失焦，派发 `HOLD_ABORT`，提示「请长按二维码」。
- 完成后松手不应重复派发事件。
- 禁止浏览器原生右键 / 长按菜单，页面只显示脱敏模拟菜单。
- 键盘用户聚焦伪二维码后，按住空格 `800ms` 等价于长按；提前松开等价于短按失败。
- 「取消」返回 H5 并要求重新长按；「转发给朋友」「保存图片」只显示演示提示，仍停在系统菜单。

## 7. 新链路状态机

### 7.1 状态

| 状态 | 画面 | 可执行事件 |
| --- | --- | --- |
| `NEW_AD` | 与原链路一致的虚构健康资料广告 | `CLAIM_CLICK` |
| `NEW_ENTRY` | 抽象承接页，文案与卡片入口同时可见 | `ACQUISITION_CLICK` |
| `NEW_LINK_LOADING` | 深色浏览器栏、白色页面和居中加载浮层 | 系统事件 `LINK_RESOLVE` |
| `NEW_CONTACT` | 深色企业联系人资料页 | `ADD_CONTACT` |
| `NEW_ADDED` | 同一联系人页的已添加状态 | 无推进事件，可重置或重播 |

### 7.2 状态转移

| 当前状态 | 事件 | 下一状态 |
| --- | --- | --- |
| `NEW_AD` | `CLAIM_CLICK` | `NEW_ENTRY` |
| `NEW_ENTRY` | `ACQUISITION_CLICK` | `NEW_LINK_LOADING` |
| `NEW_LINK_LOADING` | `LINK_RESOLVE` | `NEW_CONTACT` |
| `NEW_CONTACT` | `ADD_CONTACT` | `NEW_ADDED` |

新链路的文案入口和整张卡片都沿用用户熟悉的点击操作，并派发同一个 `ACQUISITION_CLICK`；约 `650ms` 后自动派发 `LINK_RESOLVE` 进入联系人状态，全程不进行真实网络跳转。公开规格只描述用户层交互，不记录具体承接机制与平台能力配置。

## 8. 手动模式

- 初始模式为手动，两台手机都处于各自广告起点。
- 两条链路互不联动，操作一边不会推进另一边。
- 新链路点击广告后，文案和卡片入口同时呈现，用户可任选其一继续。
- 「重置两条链路」清空计时器、长按进度、页面滚动位置和反馈，切回手动模式，两边同时回到广告起点。
- 已完成状态不自动循环。

## 9. 自动演示

### 9.1 启动与时间线

点击「自动演示」后：

1. 清空所有旧计时器和反馈。
2. 两条链路重置到广告起点。
3. 显示 `3、2、1` 倒计时。
4. 倒计时结束后，两边同时按标准成功路径推进。

倒计时结束记为 `T+0`，目标时间线如下：

| 时间 | 原链路 | 新链路 |
| --- | --- | --- |
| `T+0.0s` | 点击广告，进入 H5 | 点击广告，进入可点击承接页 |
| `T+1.4s` | 开始模拟长按 | 停留并展示文案与卡片入口 |
| `T+2.2s` | 长按完成，弹出系统菜单 | 停留并展示双入口 |
| `T+3.2s` | 停留在系统菜单 | 点击卡片，进入本地加载页 |
| `T+3.85s` | 停留在系统菜单 | 加载完成，进入联系人页 |
| `T+4.6s` | 停留在系统菜单 | 点击添加，显示已添加 |
| `T+5.0s` | 选择联系人菜单，进入联系人页 | 已完成并保持 |
| `T+7.7s` | 点击添加，显示已添加 | 已完成并保持 |

允许视觉动画存在少量渲染延迟，但状态事件顺序不得变化。新链路先完成后必须停留在 `NEW_ADDED`，等待原链路完成，以呈现操作差异。

### 9.2 用户接管

- 自动演示时，用户在任一手机内发生 `pointerdown` 或键盘操作，立即清空全部 `demo` 计时器并将模式切为手动。
- 若该交互命中了当前状态的有效控件，在暂停后继续处理同一个事件；点击空白区域只暂停，不推进状态。
- 接管后保留两边当前状态，不自动回到起点。
- 若接管时新链路处于 `NEW_LINK_LOADING`，重新注册 `navigation` 计时器完成本地跳转；不会因暂停演示而卡死在半成品状态。
- 页面切到后台时，自动演示同样停止并保留当前状态；回到前台后补齐本地页面过渡，避免后台计时器漂移。
- 自动演示只播放一次；结束后可重播或切回手动。

## 10. 对比指标口径

底部对比区不再以 `4 步 vs 3 步` 作为主结论，而是展示决定转化能否继续的操作门槛：

- `核心操作门槛`：原链路要求用户学会持续长按识别，新链路沿用熟悉的点击。
- `后续判断`：原链路还需从系统菜单选对入口，新链路的文案与卡片都可点击。
- `获客入口`：原链路为单一伪二维码，新链路为文案链接与整张卡片两个入口。
- `完成状态`：根据当前状态显示「未开始 / 进行中 / 已添加」。

自动演示仍保留两条完整路径的时序对比，但先后完成只用于还原过程，不作为核心价值结论。

## 11. 视觉与响应式规则

页面外层继续采用已批准的浅色中性视觉系统；手机内部严格服从各自视频界面，不强行统一主题。旧链路摩擦节点在外层步骤栏使用克制红色，新链路通路使用绿色。

### 11.1 视频关键帧还原矩阵

| 链路与状态 | 必须保留的界面元素 | 等位脱敏内容 |
| --- | --- | --- |
| 两条链路 `*_AD` | 黑色短视频容器、圆形返回键、右上胶囊、绿色播放按钮、顶部大字标题、居中竖版素材、关闭圆钮、底部白色 CTA 条与红色领取按钮 | 视频画面、广告标题、商品与账户名称全部重绘为虚构健康资料内容 |
| 原链路 `OLD_H5` / `OLD_HOLDING` | iOS 状态栏与灵动岛、白色小程序导航栏、红蓝标题、资料封面、红色向下提示、米色领取模块、领取名单、主伪二维码、头像列、第二伪二维码、底部固定领取条；内容区可纵向滚动 | 书名、领取人数、名单、城市、头像和资料图均为虚构；号码只显示不可关联的掩码 |
| 原链路 `OLD_MENU` | 页面整体变暗、底部白色 action sheet、转发/收藏/保存图片、联系人入口、取消按钮；首个可推进项目获得键盘焦点 | 联系人名称改为虚构顾问；不调用系统菜单或权限 |
| 原链路 `OLD_CONTACT` / `OLD_ADDED` | 浅色联系人页、头像与姓名、橙色企业标识、朋友资料、朋友圈缩略图、企业信息分组、底部添加按钮 | 头像为 CSS 虚构肖像，姓名/企业/地区/图片均为虚构 |
| 新链路 `NEW_ENTRY` | 中性承接页、公开演示标识、可点击文案与卡片入口 | 只保留用户层操作；具体承接机制、平台能力配置与真实业务内容不进入公开版本 |
| 新链路 `NEW_LINK_LOADING` | 深色浏览器栏、关闭键、脱敏域名、绿色加载线、白色页面、居中深灰加载浮层与旋转指示 | 不显示真实路径，不发起网络请求 |
| 新链路 `NEW_CONTACT` / `NEW_ADDED` | 深色联系人页、头像与姓名、橙色企业身份、朋友资料、企业信息分组、底部添加按钮 | 头像为 CSS 虚构肖像，姓名和企业改为虚构内容 |

### 11.2 视觉约束

- 不使用真实品牌 Logo、真实头像、真实商品图、真实二维码、视频截图或视频裁切素材。
- 广告画面、商品缩略图、头像、图标和伪二维码均使用 HTML/CSS 净室重绘；不得使用可扫码、可点击的真实地址。
- 伪二维码由确定性 CSS 图案构成，外观密度接近视频，但不应能被扫码识别。
- 手机内部不出现教学红框、调试边框、`work.example/link` 或「卡片任意位置」一类解释性占位文案。
- 键盘焦点使用克制的绿色内阴影，不改变元素尺寸，不遮挡视频式边框。
- 固定手机比例、步骤区域宽度和反馈区高度，状态切换不得导致整体布局跳动。
- `>= 980px`：双链路并排；每条链路内手机与步骤栏并排。
- `< 980px`：两条链路上下排列。
- `< 580px`：单手机居中，步骤栏改为两列或单列，页面不得横向滚动。
- 所有可操作区域最小触控尺寸为 `44 x 44px`；最长中文文案必须换行且不溢出。
- 支持 `prefers-reduced-motion`：减少位移动画，但不跳过状态和结果。

## 12. 组件与职责

实现保持单页、无框架，但内部职责分离：

| 单元 | 职责 |
| --- | --- |
| `TRANSITIONS` | 定义新旧链路合法事件和下一状态 |
| `dispatch(lane, event)` | 校验并执行状态转移；非法事件无副作用 |
| `renderLane(lane)` | 根据单条链路状态渲染手机和步骤栏 |
| `renderMetrics()` | 根据当前状态渲染两条链路的完成状态 |
| `scheduleAutoDemo()` | 注册 `demo` 倒计时和自动事件，不直接改 DOM |
| `scheduleLinkResolution()` | 进入加载页后注册 `navigation` 跳转，不发起网络请求 |
| `cancelAutomation()` | 清空 `demo` 计时器、保留业务状态，并补齐必要的 `navigation` 计时器 |
| `resetAll()` | 恢复确定的初始状态 |
| `bindInteractions()` | 将点击、长按、键盘和模式控件映射为事件 |

页面不需要服务端、网络请求、LocalStorage 或跨页面状态。

## 13. 错误与边界处理

- 非法事件不改变状态，也不产生界面副作用。
- 重复快速点击通过状态校验自然去重，不允许跨过中间状态。
- 重置和重播前必须清空三类计时器，避免多轮演示叠加。
- `pointercancel`、窗口失焦、切换标签页都会终止未完成长按。
- H5 长页内部滚动不应误触长按；只有在主伪二维码上按下才启动 `hold` 计时器。
- 计时器回调执行前再次核对计时器类型、当前模式和状态；状态已变化则回调失效。
